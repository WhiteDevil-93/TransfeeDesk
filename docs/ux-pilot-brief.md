## Exact generation request

Redesign the existing BaraBridge healthcare referral application as one coherent, high-fidelity product. This is a South African hospital pilot serving referring doctors/nurses and receiving teams MEU (Medical Emergency Unit), TEU (Trauma Emergency Unit), SEU (Surgical Emergency Unit), plus unit/global administrators. Current public app: https://barabridge.84-12-115-40.sslip.io/ . Do not request or use real logins, patient data or secrets. Use synthetic content only (patient initials Q.T., age 30, QA Hospital).

Goal: exceptionally clear, calm, efficient UX on a 390px-wide phone used during clinical work, with a layout system that adapts to desktop. Design real clinical workflows, not a marketing landing page. Keep the BaraBridge name and a restrained teal/white/slate brand, strong typography, generous grouping, practical density, 44px minimum touch controls, visible focus, meaningful labels, and accessible contrast. Red/amber/green are clinical priority cues with text labels; do not rely on colour alone. Avoid decorative illustrations, glass effects, gradients and oversized empty metric cards. Each screen must make its purpose, next action, back action and account context obvious.

Generate EIGHT coordinated mobile screens, arranged in journey order, with consistent components and short annotations for error/loading/empty/pending variants:
1. Home / role chooser: clear “Send a referral” vs “Receiving staff”, description of who uses each, continue-to-workspace when already signed in, existing-case follow-up and privacy as secondary actions. Installed PWA uses this neutral entry; never strands staff in referrer login.
2. Sign-in: explicit selected audience, Home and alternate entry visible. Either form accepts valid credentials and routes according to account role, without making a user re-enter credentials. Referrer-only create-account action; receiving staff accounts are provisioned by admin. Explain password recovery. Include recoverable invalid-login and session-expiry states. No public staff/admin self-sign-up or role checkbox that grants access.
3. Referrer onboarding / verification: name, profession, email, cellphone, facility/department, specialty, optional HPCSA number, username/password; clear verification outcome. HPCSA identity match is flagged for owner review (the register is public, so it never verifies on its own); staff-card upload supports that review. Pending state has “Upload staff card”, “Check verification status” and sign out/Home; roster access and new referrals are blocked until verified. Communicate what happens next without implying instant approval.
4. My consults: primary “New referral”; useful compact cards showing reference, patient initials, receiving unit, elapsed time, priority, status, unread response and latest update. Small filter/search controls, clear empty state and actionable loading failure. Make roster and account/sign-out reachable without overwhelming the clinical task.
5. New referral form / review: a short, clearly labelled stepper (“Referral”, “Clinical details”, “Review & send”) using existing required fields: receiving unit, transfer vs advice, specialty, referring contact/facility, initials, age, sex, diagnosis, history, examination including vitals, investigations, reason, suggested priority, consent; optional folder number, clinical images and location. Group fields and show relevant fields progressively; preserve entered data after validation errors and when going back. Provide cancel/back-to-consults. Review summary separates receiving team, clinical request and consent. Success state shows reference, PRIVATE follow-up code, My consults and start another. Never claim draft autosave unless explicitly marked as a proposed addition.
6. Referrer's case detail: pinned identity/status summary, distinguish “Opened” from “Accepted for transfer”, receiving-team decision/advice clearly highlighted with author/time, chronological response history including clinical images, and a straightforward “Send update / ask a question” composer. Referrers see ONLY their own cases. Back to My consults always obvious. A private-code route exists for following up an existing case without account sign-in.
7. Receiving team's queue: obvious active unit/role, compact P1/P2/P3 and overdue indicators, urgent cases first, filters for new/waiting/accepted/advice/closed, readable clinically useful referral cards, visible new follow-up indicator. Labelled phone navigation (Queue, On call, other tools); optional tools can live in More. Preserve clear home/role-switch/sign-out routes. Do not devote half a phone screen to zero-valued statistics. Receiving staff only see their unit; global admin can switch units.
8. Receiving case + administration pattern: prioritise patient/referral summary and clinical context, show advice composer, distinct actions “Accept transfer”, “Wait”, “Decline”, and “Advice only” with consequence/validation feedback. Bed/ward and transfer progress appear when relevant. Provide return-to-queue. Include a compact reusable administration panel/inset for unit staff provisioning and global-admin referrer verification (review staff card, approve/reject, result feedback); access is role-controlled. Include a small annotation describing desktop layout: sidebar navigation, queue list/detail split view, and separate admin workspace.

Cross-screen rules:
- Every entry, loading, error, pending and not-found state offers Home or a relevant next action; no navigation dead ends or icon-only guessing.
- One active authenticated account. Switching account is explicit and clears the old session; data access is controlled by the server.
- Do not present opened receipt as acceptance, advice as transfer approval, a WhatsApp draft as delivered, or browser alerts as guaranteed background push.
- Follow-up uses reference + private code; coarse status uses reference + referring phone. Neither enables an anonymous new referral.
- Keep privacy/help visible but secondary. No patient full names or ID numbers in examples.
- Preserve the established workflow and backend capabilities. Annotate any truly new capability as a proposal, not an implemented promise.
Return a consistent component and navigation system across all screens, with visual emphasis on reducing mistakes and finding the next action.
